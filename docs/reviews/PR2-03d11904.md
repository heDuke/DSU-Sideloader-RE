## 需要修改的问题

### R1 · P1：不要在读取 sparse 头之前一概拒绝未知 ZIP 条目尺寸

位置：`DsuInstallPipeline.kt:273–280`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/installer/root/DsuInstallPipeline.kt#L273-L280

普通 `ZipOutputStream` 生成的 DEFLATED ZIP 使用 data descriptor，`nextEntry.size == -1` 是合法情况。当前提前失败，连能从 sparse 头可靠获取展开尺寸的镜像也被拒绝。原有 `installImage` 路径会优先采用 sparse 头尺寸，新增的前置判断使这一输入失去支持。

复现：一个格式正确的 32 字节展开镜像，经标准 ZIP 压缩后，sparse 解析器返回 32，而 pipeline 返回 `Unknown uncompressed size for system.img (zip data descriptor)` 并清理。

建议：先识别格式。sparse 可使用经验证的头部尺寸；raw 的未知大小可预扫描/暂存，或提供明确的不支持说明。继续校验 ZIP CRC、条目结尾和实际尺寸。不能将“大小未知”直接等同于“输入损坏”。补充合法 DEFLATED sparse ZIP 成功用例。

### R2 · P1：取消与清理结果没有完整传播到界面，清理结束前即开放新任务

位置：`DSUInstaller.kt:170–179`、`HomeViewModel.kt:298–305, 368–382`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/installer/root/DSUInstaller.kt#L170-L179
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L368-L382

pipeline 已生成 `CleanupResult`，但适配器只把 `step/info` 或空取消回调传出。即使 `abort/remove` 返回 false 或抛异常，UI 也收不到清理失败信息。取消按钮先将 UI 重置为可安装状态，再取消 Job；最终取消回调仅写“cleaned up”日志。旧任务仍可能等待分区创建或执行全局 abort/remove，此时用户能启动下一任务，两个任务没有串行保障。

这是 P0 结果传播和取消完整性尚未完成，不要求在此 PR 实现完整 P1 引擎架构。用最小的任务互斥与取消中/清理中状态即可补齐。

建议：保留完整终态，清理返回后才解锁；`removed=false` 显示未清理/状态未知并提供下一步，旧任务回调按任务 ID 隔离。补充 abort/remove 失败、延迟清理期间重试以及旧回调不能覆盖新任务状态的集成测试。

证据性质：源码调用链审查；尚未用真实 gsid 复现交错操作。

### R3 · P1：离开“已提交但无法确认”页面会过早恢复 SD 卡

位置：`HomeViewModel.kt:91–116`、`InstallationCardStep.kt:244–248`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L91-L116
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/ui/cards/installation/InstallationCardStep.kt#L244-L248

无 READ_LOGS 时，onSubmitted 后立刻显示返回按钮，返回调用 resetInstallationCard 并触发 mount。此刻系统确认可能尚未完成，DSU 也可能尚未决定分配位置。重新挂载会撤销“临时卸载以避免外置卡分配”的条件。重开应用时无条件 remount 有相同问题。

“无法确认”不是终态，离开页面也不是安装结束。这不只是文案或体验选择。

建议：把临时卷记录与任务阶段关联。结果未知时不要仅依据页面返回/应用启动自动挂载；提供明确恢复操作，说明应先在系统侧完成或取消安装，再由用户恢复。能够查询平台状态的路径优先核实后恢复。补充提交、返回、重开时的挂载时序测试。

证据性质：可达 UI/调用链已确认；具体设备上触发外置卡分配错误尚未实测。

### R4 · P2：挂载失败后清空待恢复记录，无法在下次启动重试

位置：`SdCardRemounter.kt:93–102`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/installer/privileged/SdCardRemounter.kt#L93-L102

`mount(id)` 异常后只记录日志，循环结束无条件写入空列表。服务暂时断连、卷忙或权限失败都不等同于“已挂载或卡已拔出”，这样会永久丢失本次恢复责任。

注入实际 remounter 的 mount 异常后：`calls=1, persisted={pending_sd_remount=}`；`hasPending()` 返回 false。

建议：只清除确认恢复或确认不再存在的卷，保留失败卷和原因。mount 请求返回也不必然代表设备已完成挂载，应按可用状态信息核实。补充失败后保留、后续成功后清除以及部分成功/部分失败的测试。

### R5 · P2：新增长度校验不足以兜底现有 sparse 解析器的提前 EOF

位置：`DsuInstallPipeline.kt:309–331`；关联原有 `SparseInputStream.java:125–148`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/installer/root/DsuInstallPipeline.kt#L309-L331

构造的输入声明 totalBlocks=1、totalChunks=2：第一 RAW chunk 写完一块，第二 RAW chunk 声明还有一块但 payload 截断。原有解析器把第二 chunk 的提前 EOF 返回为普通 -1；这时已输出长度刚好等于文件头的展开长度。新 pipeline 接受该输入、调用 finish 并返回 Success。

独立复现：`result=Success finished=true`。

解析器问题本身来自上游；本 PR “长度不符检查已经兜底”的说法不成立，P0 的损坏输入检查还需补齐。不能据此宣称所有截断 sparse 都已安全处理。

建议：RAW payload 提前 EOF 必须抛错；验证 chunk 数量、chunk total size、块总和与文件头声明的一致性。将该组合用例和普通截断用例一并纳入回归。

### R6 · P2：关闭 raw 流没有关闭 ZipInputStream 的 Inflater

位置：`DsuInstallPipeline.kt:264–288`
https://github.com/heDuke/DSU-Sideloader-RE/blob/03d11904b5a3fdbc12dab2089c7abe40b301d433/app/src/main/java/vegabobo/dsusideloader/installer/root/DsuInstallPipeline.kt#L264-L288

目前仅 `open().use { raw -> ... }`，局部 `ZipInputStream(raw)` 没有 use/close。虽然底层文件输入流会关闭，但外层 ZIP 解压器持有的 Inflater 仍需靠 GC 清理。正常或中途失败均未确定性释放该资源，因此 P0 第 6 项“ZIP 流在所有路径关闭”尚未完成。

建议：给 ZIP 包装流本身添加 use，并继续确保构造失败时 raw 能关闭；保留单条目 NonClosingInputStream 以避免条目提前关闭整个包。补充正常和失败路径的包装流关闭验证。

证据性质：资源所有权审查；未对 Android 原生内存占用做设备测量。

## 六项待决问题的建议默认值

以下是供用户确认或直接转交开发者的建议，不代表已修改产品或源码。

1. 分区：保留显式允许列表和未知分区拒绝策略，避免静默丢失必要分区；当前 8 项视为候选集合，实际支持以 Android/OEM/后端能力验证为准。已知不可侧载的 boot/vbmeta 等可跳过，但应在安装摘要说明。尽量在分配 userdata 前完成校验。

3. system.img：本次操作是完整 DSU 安装，建议必须恰好包含一个 system；单独 vendor/product 不能作为完整系统报告安装成功。未来增量/复用已有分区须另立操作类型和前置条件。
4. SD 恢复：不采用“离开页面或重开应用即完成”的推断；按 R3 修复未知阶段的处理，并按 R4 保留失败记录。

6. 文案：建议“请求已交给系统，尚未确认安装完成。请在系统 DSU 页面确认，并查看通知中的进度。”优先解释用户下一步，权限名放在详情中。
