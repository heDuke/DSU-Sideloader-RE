## RE2 修复核对

[HomeViewModel.kt:768](https://github.com/heDuke/DSU-Sideloader-RE/blob/a6587d63403160060aaa49d86b56ad6ac1ee22c6/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L768) 的默认路径现在是：

```kotlin
systemReported: Boolean = false
val handedToSystem = !systemReported && taskGate.hasHandedToSystem(id)
```

因此，普通入口、重试、提交步骤及诊断初始化发生我方错误时，只要任务已交给系统，就默认保留未确认状态。主入口不再依赖额外传 requestFailed=true；后续新增普通调用点漏传标志也会落在保守路径。

系统日志入口 [HomeViewModel.kt:622](https://github.com/heDuke/DSU-Sideloader-RE/blob/a6587d63403160060aaa49d86b56ad6ac1ee22c6/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L622) 显式传 systemReported=true。它仍区分系统 DSU 明确报告的失败/取消，不把这些事件一概转换成“未确认”。

已检查当前所有 onTaskFailed 调用点：只有系统日志生产者标记 systemReported，其余调用使用默认保守策略。这种默认值比要求每个我方调用者主动传保守标志更合适。本轮不要求继续重构成新的事件引擎。

原 RE2 输出由此前的 ERROR、mount=1、pending=null，变为：

```text
REVIEW logging handoff:
handedAtFailure=true
card=INSTALL_SUBMITTED_UNCONFIRMED
calls=[unmount, forceStop, startActivity]
pending=PendingRemount(... phase=SYSTEM_UNKNOWN ...)
uncaught=[]
```

仓库新增的 LoggingHandoffWiringTest 还检查了错误详情、恢复状态、显式恢复和下一任务可开始；这些断言均通过。其输出中出现 mount 是后续明确点击恢复后的结果，不是异常路径自动挂载。

## 系统明确结束的对照

为了检查新的默认策略没有误伤系统终态，本轮增加 SystemOutcomeReviewTest：

1. 通过实际提取的普通 onConfirm 入口完成交接，断言任务交接标志为 true。
2. 在外部日志读取边界注入：

```text
DynamicSystemInstallationService: status: NOT_STARTED, cause: INSTALL_CANCELLED
```

3. 让真实 LogcatDiagnostic 解析文本，调用真实 startLogging 中配置的错误回调，再进入实际 onTaskFailed 与恢复逻辑。
4. 断言 ERROR_CANCELED、恢复一次、pending 清空、无协程逃逸异常、下一任务可开始。

实测：

```text
SYSTEM outcome: handoff=true actual parsed INSTALL_CANCELLED -> ERROR_CANCELED mount=1 pending=null uncaught=[]
```

该输入是注入的日志文本，不是真实手机产生的系统取消事件；验证的是生产解析与回调分类的接线。与已通过的我方日志初始化异常用例组合，证明本轮已覆盖的两类错误路径保留了区别。
