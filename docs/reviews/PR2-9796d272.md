## FR1 修复核对

1. **交接尚未完成的责任归准备侧。** [HomeViewModel.kt:365](https://github.com/heDuke/DSU-Sideloader-RE/blob/9796d2725e6eb9744f95cc685d96c3ce3110d873/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L365) 在 onErrorAfterSettle 中检查 isOwnedByPreparation。仍为 PREPARING 时，包括取消已经到达的情况，都进入准备终态处理，不再被 onTaskFailed 的 cancelling 保护丢弃。ROOT_INSTALL / DSU_APP 仍交由后端处理。
2. **清理、重复回调与兜底。** [HomeViewModel.kt:409](https://github.com/heDuke/DSU-Sideloader-RE/blob/9796d2725e6eb9744f95cc685d96c3ce3110d873/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L409) 先 claimTerminal，再清理任务自己的目录，最后上报并释放。重复的准备终态回调不会重复执行清理。已进入 report 的代码有 finally 兜底释放。取消后的交接异常、清理异常分别保留为详情。
3. **ADB 成功与取消竞争。** [HomeViewModel.kt:478](https://github.com/heDuke/DSU-Sideloader-RE/blob/9796d2725e6eb9744f95cc685d96c3ce3110d873/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L478) 使用 finishIfNotCancelling，已收到取消时改走取消终态，不会再发布“请运行 ADB 命令”的卡片。正常成功结束后才记录脚本路径。
4. **settle 后的取消也通知交接处理。** [TaskStep.kt:60](https://github.com/heDuke/DSU-Sideloader-RE/blob/9796d2725e6eb9744f95cc685d96c3ce3110d873/app/src/main/java/vegabobo/dsusideloader/installer/task/TaskStep.kt#L60) 将 settle 后的 CancellationException 交给 onErrorAfterSettle，再继续传播取消；非 Exception 的 Throwable 上报后仍重新抛出，不能将其描述为已经安全吞掉所有致命错误。

这里的 claimTerminal 主要约束准备侧收尾；不把它夸大成对所有后端、所有 Android 回调的全局 exactly-once 证明。

## 额外接线验证与证据边界

本轮继续从源码原样提取方法，执行真实 TaskSteps、InstallTaskGate、DsuSubmission、DsuInstallationHandler、PrivilegedProvider、AdbInstallationHandler、GenerateInstallationScript、InstallationCmdline，以及提取的 StorageManager.writeStringToExternalFileDir。扩展 harness 提供错误详情读取，用四个 probe 检查：

- 取消先到、真实脚本写入随后成功：仍显示 ERROR_CANCELED，任务目录清理一次，不发布脚本路径。阻塞点在外部目录查询，未声称测到了每一个“最后一字节写完”的竞争瞬间。
- 取消后写入失败且清理也失败：两类错误详情同时保留，gate 释放。
- 重复准备终态回调：清理只执行一次，清理阻塞时拒绝新任务，结束后允许下一任务。
- 没有取消时写入失败：ERROR，保留 I/O 错误，gate 释放。

Session、Preparation 文件处理、外层 scope、偏好、Settings/权限、存储上下文、IPC、Intent/DataStore 等框架边界仍使用替身；与场景无关的日志/挂载辅助函数也用替身。**不是完整 Android ViewModel/生命周期/Binder 集成测试。** 原 FR1 和本轮写入故障通过外部目录查询返回 null，异常来自生产写入方法自身。

新增的 FourthReviewRegressionTest 是按调用顺序编写的协调模型，不能替代实际接线验证；本轮原版 probe 和新增四项用于补充这一层证据。

### 关于“上报本身抛异常”的测试

独立运行 136 项测试时，exceptionWhileReportingStillReleasesGate 会输出：

```text
Exception in thread "DefaultDispatcher-worker-3" java.lang.IllegalStateException: UI update failed
...
OK (136 tests)
```

这是该模型主动注入的错误从后台协程逸出，JUnit 的锁/终态断言仍然通过。测试证明了模型里的 finally 解锁，**不证明 Android 应用在上报抛异常时不会崩溃**。建议测试显式收集并断言预期协程异常；本轮不据此新增 P1，也不把应用实际 UI 异常恢复列为已验证。
