## TR1 · P1：准备阶段清理尚未结束就解锁，会删除下一任务的工作文件

位置：`HomeViewModel.kt:382–392`，关联 `finishCancelWithOutcome:644–650` 和 `StorageManager.kt:94–99`。
https://github.com/heDuke/DSU-Sideloader-RE/blob/9090fc71704d37789d301330e68c1f3b913d5113/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L382-L392

新回调先执行：

```kotlin
viewModelScope.launch(Dispatchers.IO) {
    runCatching { storageManager.cleanWorkspaceFolder(true) }
}
```

随后立即调用取消/失败终态并释放 gate。清理协程没有被等待，也没有任务文件归属限制；cleanWorkspaceFolder(true) 会遍历删除整个共享工作目录。

执行从生产源码提取的方法，控制清理 I/O 阻塞：

1. 任务 A 取消/失败，清理协程开始但暂停。
2. A 的终态释放 gate，任务 B 被允许开始。
3. B 创建 `new-task-image.img`。
4. A 的清理继续，删除 B 的工作文件。

实测输出：

```text
newTaskAdmitted=true newTaskFileDeleted=true
```

影响是新的准备/安装数据被旧任务清理，造成安装失败或重试异常；此处指应用共享工作目录中的新任务文件，不是声称会删除工作目录之外的用户原始镜像。

最小修复要求：

- 清理在 IO 上执行可以保留，但 gate 和 CANCELLING/清理状态要等到清理结果确定后才释放。
- 或按任务 ID 隔离目录/文件归属，旧清理只能处理自己的文件。
- 不要只在测试 Coordinator 里 finish；覆盖实际终态回调和工作目录清理的顺序。
- 清理失败也要记录准确结果，不能吞掉异常后当作已干净取消。

回归要求：阻塞 A 的实际清理步骤时，B 不能获准使用同一工作目录；若采用分任务目录，释放 A 清理后 B 的文件必须仍存在。

## TR2 · P1：提交步骤发布前取消，旧调用会使用下一任务的 Job 再提交

位置：`HomeViewModel.kt:472–518`，关联 `591–599` 和 `beginTask:334–342`。
https://github.com/heDuke/DSU-Sideloader-RE/blob/9090fc71704d37789d301330e68c1f3b913d5113/app/src/main/java/vegabobo/dsusideloader/ui/screen/home/HomeViewModel.kt#L472-L518

当前顺序：

1. 将 gate phase 切为 DSU_APP。
2. 更新界面并读取设置/权限、构造 handler。
3. 用当前可变 `installationJob` 创建子协程。
4. 最后才发布 `dsuSubmission`。

取消落在第 1–4 步之间时，cancelDsuAppInstallation 可能找不到对应 step，将 null 当作“请求没到系统且已经停止”，立即 finish。

如果此时开始任务 B，beginTask 会把共享 installationJob 改为 B 的 Job。A 的旧调用恢复后，在第 3 步读取这个新 Job，导致旧提交作为 B 的子协程运行。A 的 UI 回调虽然被 ID 过滤，startActivity 副作用仍会发生。

执行生产方法片段，令 currentBootId 的 Settings 边界暂停在 step 发布前，运行真实取消方法，再创建 B、释放 Settings 读取，实测：

```text
cancel-finished-next-task=2
forceStop
startActivity-from-old-task=1 currentTask=2
```

这是已发布 step 的 cancelAndJoin 测试没有覆盖的注册窗口，不是要求更换新的提交引擎。

最小修复要求：

- 每个任务的 Job/参数在任务创建时绑定身份，旧调用不能再读取后来替换的全局 installationJob。
- phase 交接与 step 注册形成有序协议；未发布 step 不等于没有正在执行的提交准备。
- 取消在注册窗口发生时，也要等旧准备停止或完成可取消注册，再释放 gate。
- 在开始副作用前核对当前任务身份和取消状态，UI 回调过滤不能替代执行侧保护。
- 对类似读取可变 installationJob 的其他后端交接点采用一致的任务归属约束。

回归要求：在 setPhase 后、step 发布前阻塞；取消 A；尝试开始 B；放开阻塞后，A 不能 forceStop/unmount/startActivity，也不能使用 B 的 Job。需要覆盖实际接线，不仅是独立 DsuSubmission 类。
