### 实际方法复现

新增 LoggingHandoffReviewTest，不再把 startLogging 当空替身；编译真实 LogcatDiagnostic，提取真实 startLogging。只在 CmdRunner 的外部日志传输边界注入一次 IOException。

1. 先运行一次正常 tracked 请求，再正常取消、返回卡片。实际 logger 对象仍由 ViewModel 持有，这是现有字段行为。
2. 用户通过普通 onConfirmInstallationSheet 开始新安装，并启用卸载 SD 卡。不是通过 RetryEntry 发起。
3. 新请求已经完成 startActivity，提交 Job 已完成，并断言该任务 hasHandedToSystem=true。
4. 在同步日志初始化的旧 logger.destroy → 日志传输关闭/重连处抛 IOException。故障注入通过等待提交 Job，固定“先交接、后抛异常”的顺序。
5. 准备步骤已 settle，异常进入主入口 onErrorAfterSettle。它未传 requestFailed=true，直接走普通 ERROR + 自动恢复。

实测：

```text
REVIEW logging handoff:
handedAtFailure=true
card=ERROR
calls=[unmount, forceStop, startActivity, mount]
pending=null uncaught=[]

AssertionError: An app-side log initialization failure cannot confirm system installation ended
expected:<0> but was:<1>
```

forceStop 是新请求准备时的那一次；交接后的异常没有停止或验证系统安装，就挂载并清空记录。这个缺陷和是否存在未捕获协程异常无关，测试中的 uncaught 为空。没有真实设备上故障发生频率的数据，也不声称已经观察到真实 gsid 正在写盘；确定的是**日志初始化失败不能证明已交给系统的安装终止**。
